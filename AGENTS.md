## 1. Goal
A native (not emulated) New Nintendo 3DS homebrew port of Pokemon SoulSilver (US). The game's own decompiled C runs on the 3DS ARM11 CPU; a platform layer draws it with the 3DS GPU, adds stereo 3D, wide view, a settings menu and quality-of-life features. Owner: the owner (GitHub `unowncollectables`). Personal, experimental, GPL-3.0.

## 2. Hard rules (never break)
1. **Never commit ROMs, saves, extracted assets, or built binaries** (`.nds`, `.sav`, `.3dsx`, `.cia`, `.elf`). The user supplies their own US SoulSilver dump (SHA1 in `upstream.lock`). `.gitignore` blocks the common cases; check `git status` before every commit.
2. **Save safety.** The save must stay a plain 512 KiB `.sav`, byte-compatible with a real DS cart and R4-style flashcarts (round trip both ways). the owner runs a ribbon-master playthrough, so his Pokemon matter. Never modify the live `soulsilver.sav`; back it up (copy off the SD card) before any save-touching test; test on copies. Features must never write to the save unless that is their explicit purpose (the hunt counter writes `hunt.txt`, not the save).
3. **One build rule.** Feature threads do NOT each build. Each change is merged to `main` and stops. One designated builder does a single build and copies it to the SD card when the owner says "build it".
4. **Toggle rule.** Every experimental or behaviour-changing feature gets a toggle in the in-game settings menu (L+R+Y), not only `config.txt`. Remove the toggle once the owner has tested it and it is proven (example: the `gpu_blend` toggle was removed after a clean device test; `gpu_blend=0` in config.txt still turns it off).
5. **Merge policy.** Working changes may be merged to `main` without waiting for a device test as long as they have good built-in logging; the owner tests afterward. Docs-only changes need no test. Do not push to branches you were not assigned.
6. **Reuse first.** Before writing anything, check whether `3ds-platinum` or `pokeplatinum-3ds` already solved it and port the better one.
7. Separate pieces of work belong in separate threads/branches/PRs.

## 3. Architecture (one paragraph)
`pspoke` (IbrahimIrfan/pspoke, GPL-3.0, pinned in `upstream.lock`) compiles pret/pokeheartgold natively for a PSP. We retarget it to the 3DS: `toolchain-3ds/` provides `psp-gcc`/`psp-g++`/`psp-ar` wrapper scripts so pspoke's build emits devkitARM (ARM11, hard-float) objects. **Names starting `psp_`/`sceXxx` in the code are shims over real 3DS calls (libctru/citro3d), not PSP code.** `soulsilver3ds/platform/` (copied from the Platinum port) replaces pspoke's PSP renderer/audio/input: main loop, GPU 3D (`g3gpu.c`), melonDS-derived software 2D/3D cores, GPU 2D compositor (`gpucomp.c`), scaling and stereo (`gpuscale.c`), ROM cache, settings app. `soulsilver3ds/full/Makefile` links everything into `soulsilver3ds.3dsx` (and a CIA via `make cia`). Our changes to pspoke live as numbered patches in `pspoke-patches/`; game-feature edits to the staged decomp are scripted hooks.

Why pspoke and not pokeplatinum-3ds as base: see `docs/ARCHITECTURE.md`. Short version: pspoke already boots HGSS natively; pokeplatinum-3ds (GabeSud0 design) is a cleaner long-term backend and lists HGSS as its later target, but is not there yet.

## 4. Build (the owner's setup; reproduce anywhere with devkitPro)
- Host: WSL2 on the owner's PC. Repo at `~/3ds/pokemon-soulsilver-new3ds`, ROM at `~/3ds/roms/SoulSilver.nds` (outside the repo).
- Needs: devkitPro `3ds-dev` (`DEVKITPRO=/opt/devkitpro`), Python 3 + `pip install ndspy`, git, make, patch, rsync, curl, ~3 GB disk.
```sh
bash scripts/bootstrap.sh                                # clones pspoke at upstream.lock, applies pspoke-patches/
bash scripts/ss3ds_build.sh ~/3ds/roms/SoulSilver.nds    # compiles the game (long the first time); ROM read in place
cd soulsilver3ds/full && make check && make              # links soulsilver3ds.3dsx
make cia                                                 # optional HOME Menu build
```
- Cloud containers cannot do the full build reliably (devkitARM docker pulls hit rate limits); builds happen on the owner's PC via a PC session. Cloud sessions CAN smoke-test headless in Azahar (AppImage release 2126.2) using `tools/emu_smoke.sh` from the 3ds-platinum repo with paths swapped to soulsilver; DeSmuME (`desmume-cli`) is the DS reference renderer.
- Deploy: SD `sdmc:/3ds/soulsilver3ds/` (`.3dsx` in `sdmc:/3ds/`), CIA copied to `F:\cias\` and installed with FBI. The SD card on the owner's PC is drive F:.

## 6. Settings menu and config
In game press **L+R+Y** (or hold the top-left of the touch screen 0.3 s). L/R or tap = tab, up/down = row, left/right/A = change (a tooltip under the list describes the selected row; tooltips live in `kTabs` in render3ds.cpp), B/START/L+R+Y = close; changes apply on close and are written to `sdmc:/3ds/soulsilver3ds/config.txt` (`key=value`). Tabs: Display, 3D, Input, Battle, Play, Setup (rows and tooltips: `kTabs`). The Debug and Render tabs were removed 2026-11-18 for release: speed/diagnostic keys are config-only escape hatches with their tested default in `kCfgDefaults`; do not add debug rows back to the player menu. Settings indices (`mItems`) are unchanged; some old Platinum-only rows are still in `mItems` but in no tab. Adding a toggle = a config key + reader in the platform layer, a row in `kTabs` with a tooltip (watch the row-count `static_assert`; an off-by-two once tripped it), a game hook, and a log line.

## 7. Logging (your main debugging tool; the owner reads `log.txt` from the SD card)
`log.txt` is rewritten each run in `sdmc:/3ds/soulsilver3ds/` (size limit and detail level are System-tab settings; `log_level` 2 = detailed). Tags:
`[3DS]` platform/boot/memory, `[AUDIO]` mixer, underfeed and clipping, `[G3REUSE]` 3D geometry reuse/cache, `[WIDE]` wide-view state and strips, `[BTN]` input, `[BMENU]` bottom-screen Start-menu tiles, `[MINIMAP]` Bottom menu map (source, map, new cells, mode), `[GPUC]` GPU compositor stats (frames composed vs rejected), `[PREFETCH]` map zone prefetch (`zone A -> B`), `[BATTLE]` battle speed hooks, `[HINT]` move type hint (fight menu snapshot), `[CATCH]` catch info, `[DUMP]` register dump from `dump_frame=N`, `[SAVE]` save backups/imports and `sync (why): N bytes in M writes, fsync ok|FAILED` after each save, `[LOG]` log housekeeping (fsync of log.txt every 2 s, after `[SAVE]`, on HOME/sleep/crash/exit), `[BOOT]` soft-reset helpers, `[CFG]` header (version, every config.txt key with defaults, DEAD/UNLISTED flags, effective values), `[USE]` feature-usage summary at clean exit/crash, `[CONTEST]` Bug-Catching Contest card, `[QUICK]` quick actions (ZL run, ZR item, L+R+X), `[CRASH]`. Exact lines per feature: docs/HANDOFF.md "Log tags". One line per event, never per frame; add a counter row in `logring.c` `useTab` for each new feature. When you add a feature, add a tag and log its first use, its inputs, and any decision it makes.

### Audio lookup boundary fix (2026-11-08)
`psp_ctru.c` wraps `NNS_SndPlayerMoveVolume` via `full/Makefile` to saturate targets to 0..127. Field music requests 128, which otherwise reads beyond libntr's decibel table and can add +256 to player attenuation. Existing audio settings stay unchanged. Platform-only rebuild; no clean game rebuild. Logs first eight corrections as `[AUDIO] fader target ...`. Goldenrod / Route 34 verified in local Azahar with a copied save; real New 3DS validation remains outstanding. See `docs/HANDOFF.md` for evidence.

## 8. Current status

**60 fps (finished 2026-11-18, #517-#540):** mono about 60 fps, stereo close to it. The tuned 60 fps setup is the default and there are no player toggles for it. Details in root [HANDOFF.md](HANDOFF.md) and `docs/archive/`.

**Sharp game text (2026-11-19, patch 0289 + platform, cloud build and Azahar checked, not on hardware yet):** every game string goes through `CopyGlyphToWindow` (bg_window.c). Hook 0289 notes the 16x32 cell before and after each glyph, so `platform/ss3ds_gametext.c` knows exactly which pixels the text changed and what was under them (fills, scrolls, blit/fill rectangles and removal are hooked too). `CopyWindowPixelsToVram_TextMode` asks `P3DS_GtUpload` which buffer goes to VRAM: a copy with the text pixels put back to what was under them (only while the buffer still holds exactly what the glyph wrote; the game's own buffer is never changed), then `P3DS_GtLoaded` records where it landed (`BgGetCharPtr`) and its hash. Both engines, every scene, 4 bit text BGs. `gpuscale.c` `gtDraw` has a 400x240 top layer (both eyes, under toasts) and a 320x240 bottom layer (under the panel/column). A text pixel is drawn only where the BG map still shows that window's tile (with the map's palette, menus highlight rows that way), the BG is on, the DS window regions show it and no higher-priority text BG covers it; fades and alpha are applied; wide layouts place text with its moved panel (`WC_MapColumn`). Every frame the window's VRAM hash is checked (anything else wrote there = not drawn). `render3ds.cpp` sets `P3DS_GtScreensNow` per present (live engine picture only: not the Bottom menu, settings, held/black pictures, panel party); `P3DS_GtSync` at the start of each compose puts text back into VRAM for a screen that cannot show the layer (or setting OFF) and takes it out again when it can, so toggling applies at once. Toggle Settings > Display "Sharp game text" (`sharp_game_text`, default ON). Log `[GTEXT]` (screens, windows taken out/put back, layer counts with hide reasons). Lessons: the blinking down arrow blits into the window (only text under a blit/fill rectangle is forgotten); the title menu highlights the selected box by map palette (use the map entry's palette). Text copied into sprites (TextOBJ battle move names/PP, HP box names, SAFARI/PARK BALLS): those strings are printed into windows on no BG (bgId 0xFF, `AddTextWindowTopLeftCorner`); their text tiles are kept as records (printed + text-free), also after RemoveWindow. Each present `P3DS_GtSync` compares the tiles visible 4 bit non-affine sprites show with the records, swaps matches for the text-free tile for THIS present's picture only, and `P3DS_GtObjRestore` (wrapper around `Present` in render3ds.cpp) puts the printed tiles back before the game runs again: the game never sees changed OBJ VRAM and a reused tile cannot pick up old text. Touching text tiles are drawn as one block, centred where the DS picture shows it. `sub_02013A50` (unk_02013534.c, the window-to-sprite tile copy used by TextOBJ, the naming screen letters and Pokegear map markings) is hooked to snapshot any window's text tiles at copy time. 8 bit windows (e.g. the back of the trainer card, an affine BG) are handled too; a BG that is rotated/scaled (card flip), or 8 bit with extended palettes, gets its text put back into the DS picture until it is 1:1 again. Not covered: the battle Lv/HP digits and gender marks (HP box artwork, not the game font) and text in affine sprites (Wi-Fi Plaza CLOSE button).

**Sharp bottom text (2026-11-18, platform only, not built here):** the Bottom menu panel and the L+R+Y settings app used to draw their text into the 256x192 DS picture, which the GPU stretches 1.25x (uneven, blurry letters); only the side column and tab row were native. Now `kSuiText` (render3ds.cpp) records each string while the picture is painted (`ss3ds_sharptext.h`), takes it back out of the DS picture if nothing was drawn over it, and draws it at 320x240 in a text layer (`gpuscale.c` `txDraw`, between the stretched picture and the panel app / native column). Text is the game's own font at 1 font pixel = 1 screen pixel (true DS size, a little smaller than before); widths reported to layouts and touch hit tests are the native ones x4/5, so everything lines up. A string that something covers stays in the DS picture (no doubles). Off while the party/bag app is in the panel. Toggle: Settings > Display "Sharp text" (`sharp_text`, default ON, mItems row 90, the old bottom_hd slot). Log: `[TEXT] sharp panel|settings: N strings at 320x240, M left in the DS picture ...`. Host preview with the real font: `tools/sharp_text_preview.cpp`.

**Finder sprite + where to catch (2026-11-18, not built here):** the Pokedex finder card (tap a species in a place's wild list, toggle `pg_find`) draws the species' true-colour menu icon (was a washed-out mono tint) and has a LIST chip: a paged list of every place the species lives with the game's slot chances (grass morning/day/night, surf, rock smash, old/good/super rod), filtered by the ANY/MORN/DAY/NITE chips. ## 12. HeartGold (EXPERIMENTAL, same port, separate game)
HeartGold (US, `IPKE`, SHA1 `heartgold_sha1` in `upstream.lock`) is built from this same repo and the same source as SoulSilver, as a game of its own. Nothing is duplicated and the SoulSilver build does not change: with no HeartGold variable set, every script and compiler call is what it was.
- **Build:** `bash scripts/hg_build.sh /path/to/HeartGold.nds` then `make -C heartgold3ds/full` (`make cia` for the HOME Menu version). Outputs `heartgold3ds/full/heartgold3ds.3dsx` / `.cia`.
- **Own tree:** `pspoke-hg/` (its own pspoke clone, work tree and objects) and `build-hg/`. `pspoke/` and `build/` belong to SoulSilver and are never used. `scripts/bootstrap.sh` takes the folder from `SS3DS_PSPOKE_DIR` (default `pspoke`).
- **Game version:** `SS3DS_GAME=HEARTGOLD` (set by `hg_build.sh`) makes `toolchain-3ds/bin/psp-gcc`/`psp-g++` turn `-DSOULSILVER` into `-DHEARTGOLD` and add `-DHEARTGOLD` when preprocessing assembly (the translator passes no game define). The decomp does the rest (`#ifdef HEARTGOLD`, `GAME_VERSION`).
- **Own names:** `scripts/hg_rename.py` is a name filter. `tree` edits `pspoke-hg` in place (SD paths, ROM header check `IPKE`); `copy` writes filtered copies of `soulsilver3ds/platform/`, the link Makefile and the CIA files into `heartgold3ds/` (generated, gitignored); `check` stops the build if the linked program still names `soulsilver3ds`, `soulsilver.sav` or `soulsilver.nds`. So HeartGold uses `sdmc:/3ds/heartgold3ds/` with `heartgold.nds` and `heartgold.sav`, and HOME Menu title `000400000F7D4100` (`CTR-H-HG3D`; SoulSilver is `...F7D4000`). It can never open the SoulSilver save.
- **Rule for platform code:** keep writing SoulSilver paths as today (`sdmc:/3ds/soulsilver3ds/...`, `soulsilver.sav`); the filter renames them for HeartGold. For code that must differ between the games use `#ifdef SS3DS_HEARTGOLD` (platform) or `#ifdef HEARTGOLD` (game code). Do not edit anything under `heartgold3ds/platform/` or `heartgold3ds/full/gen.mk`: they are rewritten at every build.
- **Committed HeartGold files:** `scripts/hg_build.sh`, `scripts/hg_rename.py`, `tools/find_rom_hg.sh`, `heartgold3ds/full/Makefile`, `heartgold3ds/full/cia/art/` (original gold icon and flat banner; `cia/dev/make_hg_art.py` remakes them).
- **ROM check:** `scripts/hg_romcheck.py` accepts the exact dump (`heartgold_sha1`) or a US `IPKE` ROM whose data files and overlays all match it (`heartgold_files_sha1`; only the unused boot code differs, as in the owner's dump).
- **Banner:** `BANNER=3d` (default) runs `tools/banner3d/make_banner.py --game heartgold`: the title screen's Ho-Oh from the HeartGold ROM at build time, gold art in `tools/banner3d/art-hg/`, packed by `tools/banner3d/fit_parts.py` to pass the same Platinum structure check as Lugia. The Lugia banner is byte-identical (checked before/after). Any failure -> flat banner.
- **Status (2026-11-10):** first full build done in a cloud container (devkitARM copied from the `devkitpro/devkitarm` image): game compile, link, `.3dsx` and `.cia` with the Ho-Oh banner all succeed, `gGameVersion` in the program is 7 (HeartGold), and `hg_rename.py check` passes. **Never run**: not on a console, not in an emulator. Online play needs its own test (the ROM game code is passed through). Patch 0265 (nine comm helper seeds, a link fix needed after 0264) came out of this build and applies to both games.
