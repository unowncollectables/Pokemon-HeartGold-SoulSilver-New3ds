# README capture notes

Captured on 19 November 2026 from SoulSilver main `5e39a63d3412facf1c5df21f038a696e80e161a0`, built locally with devkitARM. The full game build, `make check`, and final 3DSX link completed successfully. This includes the finder readability fix merged in [PR #566](https://github.com/unowncollectables/Pokemon-HeartGold-SoulSilver-New3ds/pull/566), found and verified during this capture pass.

[Jules (estyseesghosts)](https://github.com/estyseesghosts) created [LOTUS/CITnLO](https://github.com/estyseesghosts/lotus) and [SAV4HGSS-cli](https://github.com/estyseesghosts/SAV4HGSS-cli). Her tools enabled the direct screen captures, reproducible input, and disposable warp/story scenes used here. Thank you, Jules, for making these tools available.

LOTUS v0.0.6 with its CITnLO worker (`c3422b0a712b14cdeabc638693a55d733b43e524`) supplied direct 400×240 top and 320×240 bottom framebuffers. The emulator profile selected New 3DS and the software renderer. These images demonstrate appearance, not hardware performance or stereoscopic depth. The README’s overworld performance statement comes from the project’s recorded hardware pass, not this emulator session.

The tour used a fixed morning clock in November, seasonal trees and Ambient Weather enabled, camera settings for framing, and achievement popups/FPS counter disabled. Ambient Weather is optional and currently defaults OFF; the capture setup does not change the documented defaults.

SAV4HGSS-cli prepared warp locations on disposable copies of a cartridge-format save. Normal movement after loading restored the follower before the scenic shots. Party order was changed in the game for the Geodude shots. The Groudon battle uses a separately staged, compatible SoulSilver postgame scene. No live SD-card save or configuration was changed, and no ROM, save, config, extracted sprite or build binary belongs in this directory.

Paired screenshots retain both screens at native resolution, with the narrower bottom screen centered below an eight-pixel separator. Interface close-ups use the captured bottom screen. Scenery images use the captured top screen; the two Bellchime images are framed as 400×190 crops. Pixels were not repainted, enhanced or generated. The GIF cycles selected full paired captures at 2.3 seconds each; it is a gallery tour, not a motion or frame-rate comparison.
